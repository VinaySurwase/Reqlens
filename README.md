# Reqlens

A job-search backend that pulls postings from several public sources, keeps them fresh, removes cross-source
duplicates, extracts structured fields with an LLM, and supports lexical, dense, hybrid and reranked search plus
a small tool-using search agent.

## What is included

**Ingestion** (`src/reqlens/sources`, `src/reqlens/ingest`)
- Adapters for Greenhouse boards, Lever boards, Hacker News "Who is hiring?" and Remotive.
- Shared HTTP client with retries, backoff, timeouts and an on-disk response cache.
- Idempotent ingest with a freshness lifecycle: content hashing, new/changed/unchanged tracking, and expiry
  only after repeated misses on a fully successful run. Partial or failed runs never expire postings.

**Extraction** (`src/reqlens/extract`)
- Pydantic-validated schema: seniority, years of experience, remote type, location, skills, employment type.
- Gemini structured-output extractor with one validation retry, plus a regex baseline extractor.
- Resumable worker with quota-aware backoff; every LLM call is logged to `llm_calls`.

**Deduplication** (`src/reqlens/dedup`)
- Company blocking, then a weighted score (title, description similarity, location, seniority).
- Hard vetoes for internship mismatch, conflicting cities, distant seniority levels, and distinct postings from
  the same source.
- Incremental clustering into canonical `jobs`, with all apply URLs preserved. Raw postings are never deleted.

**Search** (`src/reqlens/search`)
- Postgres full-text search, pgvector cosine search (HNSW), Reciprocal Rank Fusion hybrid, and optional LLM rerank.
- Structured filters (remote type, seniority, years of experience, skills, company, recency, internship).
- Graceful fallback to lexical or hybrid order if embeddings or reranking are unavailable.

**Agent** (`src/reqlens/agent`)
- Two validated tools (`search_jobs`, `get_job_details`), bounded steps and time budget.
- Server-side checks: unseen/hallucinated job IDs are dropped, and constraints that depend on unknown fields are
  reported as uncertain rather than matched.

**Storage**: PostgreSQL 16 with pgvector, schema managed by Alembic.

## Requirements

- Python 3.11+
- PostgreSQL 16 with the `pgvector` extension (a Docker Compose file is provided)
- A Gemini API key for real extraction and embeddings (optional for offline runs, see below)

## Setup

```bash
docker compose up -d db
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env            # then edit values
alembic upgrade head
```

## Usage

Run the full pipeline (ingest, extract, dedup, index) for configured sources:

```bash
reqlens pipeline --sources greenhouse lever hn remotive
```

Company boards for Greenhouse and Lever are listed in `config/boards.yaml`.

Run everything offline on a bundled synthetic dataset (fictional companies, no network or API key needed):

```bash
export RL_EMBEDDING_PROVIDER=hash RL_EXTRACTION_PROVIDER=heuristic
reqlens seed-demo
```

Search from Python:

```python
from reqlens.db.session import make_session_factory
from reqlens.llm import build_embedder
from reqlens.search.engine import search
from reqlens.search.filters import SearchFilters

with make_session_factory()() as session:
    res = search(session, "backend python engineer", mode="hybrid", k=10,
                 filters=SearchFilters(remote_type=["remote"]), embedder=build_embedder())
    for hit in res.results:
        print(hit.title, hit.company, hit.apply_urls)
```

## Configuration

All settings are environment variables with the `RL_` prefix (see `.env.example` and
`src/reqlens/config.py`): database URL, Gemini key and model names, provider switches, expiry threshold,
dedup weights and threshold, search depths, agent limits.

## Tests

```bash
pytest
```

Tests run against a real Postgres + pgvector database (default
`postgresql+psycopg://ghost:ghost@localhost:5432/reqlens_test`, override with `RL_TEST_DATABASE_URL`).
The schema is created through the Alembic migration. Source APIs are exercised through bundled fixtures
generated by `scripts/make_fixtures.py`; no network access is needed.

## Project layout

```
alembic/                 database migrations
config/boards.yaml       company boards to ingest
scripts/make_fixtures.py synthetic fixture generator
src/reqlens/
  sources/ ingest/       adapters and ingest lifecycle
  extract/               schema, extractors, worker
  dedup/                 scoring, clustering, canonical jobs
  index/                 embedding text and indexer
  search/                filters and search modes
  agent/                 tool-using search agent
tests/                   unit and integration tests
```
